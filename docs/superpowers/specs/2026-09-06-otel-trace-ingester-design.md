# OTel Trace Ingester Design

**Status**: complete (2026-09-06)
**Source**: Wave 5 followup #1 (architectural)
**Wave**: post-Wave 5 (Wave 6 candidate)

## Context

`akosha.mcp.tools.otel_tools.query_local_traces` reads traces from
`HotStore.query_traces()`. Today, traces only land in `hot_store` via the
`BodaiToolInvocationSubscriber` Redis XREADGROUP path (websocket feed),
which means traces are limited to tool invocations made through the
Bodai tool framework. Any OTel spans emitted by ad-hoc Bodai components
(via the OTel SDK directly, or via a third-party collector) are invisible
to `query_local_traces`.

This is the second-order gap behind the Wave 5 `mcp-surface-health-illusion`
finding: even after wiring `CodeGraphIngester` + kg population, the trace
feed (`local_traces_feed`) is still empty for components that don't go
through the Bodai Redis pipeline.

The fix is an **OTel trace ingester** that polls an OTLP/HTTP collector
endpoint, normalizes spans into `HotRecord`s, and writes them through the
existing `HotStore.insert` path.

## Approach

**OTel source contract**: Pull from an OTLP/HTTP collector's `/v1/traces`
endpoint, parameterized by a per-`system_id` timestamp watermark.

**Storage mapping**: Span-per-`HotRecord`. Each OTel span becomes one
`HotRecord`:

| Field | Source |
|---|---|
| `system_id` | `resource.attributes.service.name` (or explicit config) |
| `conversation_id` | `span_id` (16-hex), prefixed with `system_id` to avoid collision |
| `content` | JSON dump of `{name, kind, start_time, end_time, attributes, status}` |
| `embedding` | Generated by the existing `EmbeddingService.generate(content)` |
| `timestamp` | `start_time_unix_nano` |
| `metadata.attributes.task_class` | `attributes.task.class` (semantic attribute), used by `query_local_traces` filter |
| `metadata.otel` | Full span payload for forensic recall |

**Dedup**: Per-system-id timestamp watermark. Watermark = max(`start_time_unix_nano`)
of successfully-inserted spans. On restart, default to "1 hour ago" to
bound recovery scan size; operator can override with `AKOSHA_OTEL_INITIAL_LOOKBACK_SECONDS`.

## Components

### `akosha/ingestion/otel_ingester.py` (new)

```python
class OtelTraceIngester:
    """Pull-based OTel trace ingester.

    Polls an OTLP/HTTP collector for spans newer than the per-system-id
    watermark and writes them as HotRecords. Mirrors CodeGraphIngester's
    lifecycle shape.
    """

    def __init__(
        self,
        hot_store: HotStore,
        embedding_service: EmbeddingService,
        otlp_endpoint: str = "http://localhost:4318/v1/traces",
        poll_interval_seconds: int = 60,
        max_spans_per_poll: int = 500,
        initial_lookback_seconds: int = 3600,
    ) -> None: ...

    async def start(self) -> None: ...
    async def stop(self) -> None: ...

    # Internal polling lifecycle
    async def _polling_loop(self) -> None: ...
    async def _fetch_spans(self, since: datetime) -> list[dict[str, Any]]: ...
    def _normalize_span(self, span: dict[str, Any]) -> HotRecord: ...
    async def _ingest_span(self, record: HotRecord) -> None: ...
    def _update_watermark(self, system_id: str, span: dict[str, Any]) -> None: ...
```

### Lifespan integration

Add an `OtelTraceIngester` block to the existing lifespan in
`akosha/mcp/server.py`, mirroring the `CodeGraphIngester` block:

```python
_code_graph_ingester: Any | None = None
_otel_trace_ingester: Any | None = None

# In lifespan startup, after CodeGraphIngester is constructed:
if not os.getenv("AKOSHA_SKIP_OTEL_INGESTER"):
    _otel_trace_ingester = OtelTraceIngester(
        hot_store=hot_store,
        embedding_service=embedding_service,
        otlp_endpoint=os.getenv("AKOSHA_OTLP_ENDPOINT", "http://localhost:4318/v1/traces"),
        poll_interval_seconds=int(os.getenv("AKOSHA_OTEL_POLL_SECONDS", "60")),
    )
    await _otel_trace_ingester.start()

# In lifespan shutdown:
if _otel_trace_ingester is not None:
    await _otel_trace_ingester.stop()
    _otel_trace_ingester = None
```

### `/health` extension

The existing `local_traces_feed` aggregate (added in Wave 5) already
surfaces `feed_entities_count` and `last_updated_timestamp`. The new
ingester writes through the same path, so the existing aggregate picks up
the new spans automatically. Add a new aggregate field:

- `local_traces_feed.otel_ingester_running: bool` (was `false`; becomes
  `true` when the new ingester is started)
- `local_traces_feed.otel_endpoint: str` (the configured OTLP endpoint,
  for ops debugging)

## Data flow

```
┌─────────────────────────────────────────────────────────────┐
│  OTLP/HTTP collector (e.g. otel-collector on :4318)         │
│  POST /v1/traces                                            │
└──────────────────┬──────────────────────────────────────────┘
                   │ (pulled by OtelTraceIngester)
                   ▼
┌─────────────────────────────────────────────────────────────┐
│  OtelTraceIngester                                          │
│  • _fetch_spans(since=watermark) → HTTP GET /v1/traces      │
│  • for each span:                                           │
│      content = json(name, kind, start, end, attrs, status)  │
│      embedding = embedding_service.generate(content)        │
│      record = HotRecord(system_id, span_id, content, ...)   │
│      await hot_store.insert(record)                        │
│      watermark = max(watermark, start_time_unix_nano)       │
└──────────────────┬──────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────────────┐
│  HotStore (DuckDB)                                          │
│  conversations table — queryable via query_local_traces     │
└─────────────────────────────────────────────────────────────┘
```

## Error handling

| Failure | Behavior |
|---|---|
| OTLP collector unreachable | Log + skip poll cycle. Worker stays alive. |
| OTLP returns 5xx | Same as unreachable; backoff `min(2 * poll_interval, 300s)` |
| Span missing required fields | Log + skip that span. Continue with next. |
| Embedding service timeout | Log + skip that span. Continue with next. |
| `HotStore.insert` raises `ValueError` (dim mismatch) | Log + skip span. Do NOT advance watermark. |
| `HotStore.insert` raises `RuntimeError` (not initialized) | Same as dim mismatch. |
| Watermark file unreadable | Default to "now - initial_lookback_seconds". |

The watermark is **only** advanced on successful insertion. A span that
fails to insert will be re-attempted on the next poll cycle.

## Testing

### Unit tests

- `tests/unit/test_otel_trace_ingester.py` (new):
  - Polls OTLP endpoint at `start()`; stops cleanly at `stop()`
  - Normalizes a span to `HotRecord` with correct fields
  - Calls `embedding_service.generate(content)` once per span
  - Calls `hot_store.insert(record)` once per span
  - Watermark advances only on successful insert
  - Skips a poll cycle when the OTLP endpoint is unreachable
  - Skips a span when the embedding service times out
  - Skips a span when `hot_store.insert` raises
  - Defaults to `now - initial_lookback_seconds` when watermark is unset

## Configuration

| Env var | Default | Purpose |
|---|---|---|
| `AKOSHA_OTLP_ENDPOINT` | `http://localhost:4318/v1/traces` | OTLP/HTTP collector endpoint |
| `AKOSHA_OTEL_POLL_SECONDS` | `60` | Poll cadence |
| `AKOSHA_OTEL_MAX_SPANS_PER_POLL` | `500` | Bounded batch size |
| `AKOSHA_OTEL_INITIAL_LOOKBACK_SECONDS` | `3600` | Restart recovery window |
| `AKOSHA_SKIP_OTEL_INGESTER` | unset | Test opt-out (matches `AKOSHA_SKIP_CODE_GRAPH_INGESTER` pattern) |

## Out of scope

- Push-based ingestion (OTel SDK receiver). Polling only.
- OTLP/gRPC collector support.
- Span enrichment (e.g. joining with `KgBuilder` to add entity links).
- Watermark persistence across process restarts (in-memory only; restart
  defaults to `initial_lookback_seconds`).
- Cross-process dedup (single-process assumption, same as `CodeGraphIngester`).
